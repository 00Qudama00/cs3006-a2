# Program 2 - vector utilization (N=10000)
Width  Utilization  Total vector instructions
  2      77.9%        167727
  4      70.7%         97075
  8      67.0%         52877
 16      65.2%         27592
Trend: utilization FALLS as width grows. The while(count>0) loop runs
until the largest exponent in the vector is done. Exponents are random
0-9. With 2 lanes both are usually similar. With 16 lanes it is very
likely at least one lane has exponent 9, so all 16 lanes keep looping
while most are masked off. Wider vector = more divergence = more waste.
Both CLAMPED EXPONENT and ARRAY SUM passed at every width.

# Program 3 - ISPC mandelbrot
Part 1 (SIMD only): view1 4.59x, view2 4.12x. Ceiling W = 8.
  Shortfall because mandel() diverges: lanes that escape early are
  masked off but still occupy the vector until the slowest lane in the
  gang finishes. Makefile also uses --opt=disable-fma and
  -ffp-contract=off to keep serial and ISPC bit-identical, which costs
  some throughput.
Part 2 (tasks): ceiling C x W = 4 x 8 = 32. See sweep results.

# Program 4 - sqrt
Random input (starter):  serial 1141.7 ms, ispc 314.0 ms, task 52.1 ms
                         3.64x ISPC, 21.92x task ISPC
MAX input (all 2.998f):  serial 2754.3 ms, ispc 422.1 ms, task 94.4 ms
                         6.53x ISPC, 29.17x task ISPC
MIN input (1 of 8 hard): serial  269.7 ms, ispc 322.4 ms, task 59.8 ms
                         0.84x ISPC, 4.51x task ISPC
MAX: every lane needs the same large iteration count, no lane is ever
idle, so SIMD is fully used. 6.53x of the W=8 ceiling.
MIN: one expensive element per 8-wide gang, the other 7 converge after
one iteration but must wait. ISPC is SLOWER than serial (0.84x) because
the vector does 8 lanes of work to get 1 lane of useful result, plus
gather/scatter overhead. This is the worst case and SIMD is a net loss.
Task version still wins in both cases because multi-core parallelism is
unaffected by lane divergence.

# Program 5 - saxpy
5 runs ispc: 24.910 / 14.557 / 14.892 / 16.786 / 14.702 ms
Best: 14.557 ms = 20.473 GB/s.  Spread 11.96 - 20.47 GB/s.
Tasks: 0.99x and 0.82x - no benefit.
Hardware: Lenovo ThinkPad T480s, LPDDR3-2133, dual channel, soldered.
Theoretical peak = 2 channels x 8 bytes x 2133 MT/s = 34.1 GB/s
Measured 20.5 GB/s = 60 percent of theoretical peak.
saxpy does 2 FLOPs per 16 bytes moved, so it is completely memory bound.
One core already saturates most of the bandwidth, which is why adding
tasks does not help - the bottleneck is DRAM, not compute.
